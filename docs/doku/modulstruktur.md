# Modulstruktur und Strukturprüfungen

Diese Datei hält Schichten, Orte der Fachbereiche, Namensregeln und die automatischen Strukturprüfungen fest.

## Schichten

Der Code ist nach Schichten geordnet; ein Fachbereich darf über mehrere Schichten verteilt sein, hat aber je Schicht genau einen Einstieg (Modul-Interface oder Ordner).

| Schicht           | Inhalt                                                            |
| ----------------- | ----------------------------------------------------------------- |
| `src/components/` | Oberfläche (React-Komponenten)                                    |
| `src/hooks/`      | React-Hooks: Zustand, Abläufe, Anbindung an Fachmodule            |
| `src/lib/`        | Fachlogik und Plattformanbindung ohne React                       |
| `src/mobile/`     | mobile Wurzel                                                     |
| `src/test/`       | gemeinsame Testhilfen, nach Fachbereich in Unterordnern           |
| `src-tauri/src/`  | Rust: Fenster, Menüs, Dateisperren, Importvorgänge, Startaufgaben |

Schichtregel: `lib` verwendet keine Hooks und keine Oberflächen; `hooks` verwenden keine Oberflächen. Domain, Darstellung und Helfer bleiben unabhängig von React, Tauri und Fachabläufen. Die Regeln stehen in [scripts/automatisch/dependency-cruiser.cjs](../../scripts/automatisch/dependency-cruiser.cjs).

## Module und Interfaces

Was ein Modul ist und welche Regeln für Modulordner, Interfaces und Submodule gelten, steht im Skill [mod](../../.agents/skills/mod/SKILL.md). Ergänzend gilt im Projekt:

- Die Modulbeschreibung steht im Kopfkommentar des Interfaces, nicht doppelt in einer Datei darunter.
- Ein Interface darf breit sein, wenn das Modul viele Aufgaben hat.
- Besitzer von MarkierungsXML und MarkierungskonflikteXML ist allein [markierungs-xml](../../src/lib/markierungen/markierungs-xml/markierungs-xml.index.ts).
- Dateizugriff und Dateisperre bilden das Submodul [dateizugriff](../../src/lib/persistenz/kern/dateizugriff/dateizugriff.index.ts) des Persistenzkerns; die Kern-Dateien greifen über dessen Interface zu, nach außen bleibt `kern.index.ts` der Zugang. Weil die Persistenz als Hülle des Dateisystems gilt, dürfen Tests außerhalb des Kerns allein dieses Interface als Attrappe ersetzen (Vermerk `attrappeVonAussen` mit Grund am Moduleintrag); gewöhnliche Importe bleiben auf `kern.index.ts` beschränkt.
- Testzugang = exportierter Interface-Name, den außerhalb des Modulordners nur Tests nutzen; braucht einen begründeten Eintrag in [interface-namen-testzugaenge.json](../../scripts/automatisch/interface-namen-testzugaenge.json).
- Attrappe = in einem Test eingesetzter Ersatz eines Moduls oder einer externen Abhängigkeit (`vi.mock` u. ä.); für sie gelten dieselben Modulgrenzen wie für Importe.
- Große Ordner werden nur geteilt, wenn sie klar erkennbare Inhaltsgruppen haben; die Ordnergröße wird nicht automatisch geprüft.

## Namensregeln

| Gegenstand   | Regel                                                                                                                                   |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| Ordner       | klein; deutsche Komposita bleiben ein Wort (`gesetzestextansicht`); Bindestrich nur zwischen eigenständigen Begriffen (`import-export`) |
| Punkt-Präfix | nur, solange der Restname ohne Präfix nicht verständlich oder eindeutig wäre; in Unterordnern entfällt es                               |
| Dateinamen   | im ganzen Repository eindeutig, auch für Rust-Dateien (`.rs`, vollständiger Name mit Endung)                                            |
| Komponenten  | PascalCase; Hooks `useX.ts`; sonst camelCase                                                                                            |
| Rust         | Modulordner mit Unterstrich (Bindestriche sind in Rust-Modulnamen nicht möglich)                                                        |
| Begriffe     | Ordner- und Dateinamen verwenden Glossarbegriffe ([Glossar](../GLOSSAR.md))                                                             |

## Strukturprüfungen

| Prüfung              | Inhalt                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | Lauf                                                   |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| Modulgrenzen         | Schichtregel, Zugang nur über Interfaces, Bereichsregeln für `src/` und `scripts/` ([scripts/automatisch/dependency-cruiser.cjs](../../scripts/automatisch/dependency-cruiser.cjs))                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | `npm run pruefen`, Pre-Commit                          |
| Kreisprüfung         | Laufzeitkreise auf Modul- und Dateiebene; reine Typimporte zählen nicht. Jeder Kreis ist ein Fehler, keine Ausnahmen; jeder Fehlstart der Prüfung scheitert ebenfalls ([Skript](../../scripts/automatisch/modulzyklen-pruefen.mjs))                                                                                                                                                                                                                                                                                                                                                                                                                      | `npm run pruefen`, Pre-Commit                          |
| Modulgrenzen         | Schichtregel, Zugang nur über Interfaces, Bereichsregeln für `src/` und `scripts/` ([scripts/automatisch/dependency-cruiser.cjs](../../scripts/automatisch/dependency-cruiser.cjs))                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | `npm run pruefen`, Pre-Commit                          |
| Durchreichen         | ESLint-Regel: ein Interface bietet keinen Namen unter anderem Namen an (`export { default as X }` ausgenommen; erfasst auch `export const y = x` und `export type Y = X`) und gibt nichts aus Dateien außerhalb seines Modulordners weiter; Namen aus eigenen Submodulen sind erlaubt. Ausnahmslos ([Regel](../../eslint-rules/interface-durchreichen.cjs))                                                                                                                                                                                                                                                                                              | `npm run pruefen` (Lint), Pre-Commit bei Regeländerung |
| Interface-Namen      | Jeder exportierte Name muss außerhalb des Modulordners genutzt werden; ungenutzte Namen sind ausnahmslos Fehler. Ein nur von Tests außerhalb des Modulordners genutzter Name braucht einen begründeten Eintrag in [interface-namen-testzugaenge.json](../../scripts/automatisch/interface-namen-testzugaenge.json); ein überholter Eintrag ist ein Fehler ([Skript](../../scripts/automatisch/interface-namen-pruefen.mjs))                                                                                                                                                                                                                              | `npm run vollpruefen` (`vollpruefen:interface-namen`)  |
| Dateinamen           | eindeutige Dateinamen einschließlich `.rs` ([Skript](../../scripts/automatisch/doppelte-dateinamen.mjs))                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 | `npm run pruefen`, Pre-Commit                          |
| Ungenutzter App-Code | Jeder Export und jede Datei unter `src/` muss vom App-Code (Einstiege `src/main.tsx` und Ziehvorschau) genutzt werden; Nutzung nur durch Tests zählt nicht. Ausgenommen sind Testhilfen unter `src/test/` und Testzugänge; ein Testzugang deckt nur die Interface-Zeile ab, nicht die Funktion oder den Typ dahinter. Ungenutzter Code wird samt der Tests gelöscht, die nur ihn prüfen; Unterdrückung oder künstliche Nutzung ist unzulässig, Knip-Tags (`@public`, `@beta`, `@alias`, `@internal`) sind verboten ([Skript](../../scripts/automatisch/ungenutzter-app-code.mjs), [Tag-Verbot](../../scripts/automatisch/keine-knip-unterdrueckung.mjs)) | `npm run pruefen`                                      |

## Entwicklerlauf nur im Entwicklungsbau

Beschaffungs- und Präfixläufe ([Entwicklerlauf](entwicklerlauf.md)) starten die Entwicklungs-App. Startabfrage und Ladeblock in [main.tsx](../../src/main.tsx) laufen nur im Entwicklungsbau (`import.meta.env.DEV`); das Rust-Modul [praefixlauf](../../src-tauri/src/commands/praefixlauf.rs) und seine Befehle werden nur mit `debug_assertions` gebaut. Das ausgelieferte Programm enthält den Entwicklerlauf nicht und fragt beim Start nicht danach. Das sichert [entwicklerlauf-nur-entwicklungsbau.test.ts](../../scripts/automatisch/entwicklerlauf-nur-entwicklungsbau.test.ts).
